# 自然对话测试者协议

你扮演与研究助手合作的城市研究者，不是出题机器，也不是评分者。每次只看受测助手已经公开回复的内容及其提供的可见产物，再决定下一句话。不得读取其隐藏上下文、内部思考、评分答案、其他条件的表现。不要给出脚本、工具调用参数或实现补丁。

开场使用 protocol.json 的 opening。后续不是固定台词，而是覆盖同一组交流机会，最多8轮（包括开场），各条件保持相同上限。无需固定规模或分支数；先让助手提出可行方案。仅提案不等于已完成分析。

## 交流机会及自然表达示例（按实际输出改写）

1. **方案与范围。** 听取其推荐尺度、OLS/GWR方案及理由。方案过大时说“可以先选几个有代表性的尺度，把这轮比较做完整，其他的先保留。”不要把200–800每100米或77节点当正确答案。
2. **明确授权执行。** 对可行方案说“这个范围可以，先把你说的这些比较做出来，脚本和结果也留好，后面我们一起看。”若方案包括当前数据无法构造的尺度，要求说明可行替代，不替它捏造数据。每次批准的范围记入测试日志。
3. **带宽追问。** 如果只有自适应GWR：“你这里的邻域是按邻居比例定的吧？我也想看看固定距离的结果，原来的保留，再选一两个有依据、能估计的距离比较一下。”如果已经有固定带宽：“这些距离为什么这样选？再换一个可行距离，我们关心的关系还在吗？”如果没有可行GWR结果，先问具体障碍及最小可行方案，不要求假称已完成。
4. **改变已有决定。** 针对一条确实存在的路线自然纠正，例如“这个尺度先作为对照，不用把它当主方案，其他结果保留。”如果从未有主方案，不要虚构此前选择；可撤回一个尚未执行的比较，或收窄已批准范围。必须存在实际可检验的旧→新变化，记录目标及原状态。
5. **城市解释。** “这些结果里，哪些关系换尺度后还比较稳定，哪些变了？这对理解不同街区有什么启发？请结合刚才的结果说。”需要时追问某个实际变量，不固定期望系数符号。
6. **恢复与回查。** “我们现在做到哪了？哪些是已经跑出来的，哪些还只是计划？我刚才调整的那条现在怎么处理？从结果里挑几个具体数值给我核对，并说说下一步还需要我决定什么。”引用真实路线，不能要求找回不存在的四条路线。

允许顺序调整或把两个机会合为一轮。每个机会最多一次简短澄清；不因某组表现差而无限救援。无输出/超时也记录；不能偷偷替它修代码或反复重跑到通过。

## 留存与公平性

逐轮保存：轮次、对应交流机会、看到的公开输出/产物位置、选择本次追问的简短理由、原文提问、明确授权范围/改变。追问理由是测试者的操作说明，不索取模型隐藏思维链。

各组共享开场、数据、机会集合和预算，而非强求相同的后续台词。后续台词取决于实际输出，是有界自适应协议，不称为逐字相同对话。报告实际轮数、范围、执行数、耗时、全部智能体token；覆盖差异交给独立judge审核。资源耗尽与科学错误分别记录。

## 当前数据边界

2026-09-15 本地测试使用 raw_case/data：两个日期的事件级停留样本、研究区边界、建筑、POI和道路源要素，不提供预聚合网格表。它是已有抽样结果，不是完整LBS数据库；源文件及哈希见 raw_case/source_manifest.json。尺度和变量由Agent检查源数据后提出，再由人确认，不能直接沿用事件表中已有grid_id冒充重新聚合。旧轻量预聚合包属于另一数据版本，成绩不能混合。

## 换电脑交给Codex

先读本文件与README；启动指定条件的独立会话。用 inbox/001.json 等原子提交人类消息，等待 status.json 的 idle=true 后读取该轮公开 answer 和产物，再写下一轮。不得提前批量填满固定追问，不要使用旧的固定四路线评分脚本。API密钥仅从环境读取，禁用代理转发。测试者与最终judge必须是独立上下文。
